# Font policy

Font selection originated in [#15](https://github.com/devosurf/deckflip/issues/15); Office identity is separated in [#32](https://github.com/devosurf/deckflip/issues/32), Deck font assets are pinned in [#34](https://github.com/devosurf/deckflip/issues/34), the redistributable default is bundled in [#35](https://github.com/devosurf/deckflip/issues/35), and portable editable embedding is the default in [#36](https://github.com/devosurf/deckflip/issues/36), under the [#30 font cutover](https://github.com/devosurf/deckflip/issues/30).

## Resolution and Office identity

- For every run, the computed `font-family` stack selects the first available concrete family. A family the Slide's document declares with `@font-face` matches only those rules, first by `font-stretch` (percentage or range), then `font-style`, then `font-weight`, following CSS Fonts 4 §5.2, never an installed face of the same name (see [Deck font assets](#deck-font-assets)). The bundled default uses supplied faces rather than installed copies. Any other family matches installed faces by their preferred and legacy family names, case-insensitively, with the same CSS matching order and widths from `OS/2.usWidthClass`. Normal stretch (100%) is omitted from measured run serialization.
- A **Resolved font** separates `cssFamily` and `aliases`, `asset` (SHA-256 of the face's sfnt bytes, zero-based collection `faceIndex`, PostScript name, `source`), and `office` (`family`, `style`). `source` says where the bytes came from: `installed` (`file`), `file` (a local font file the Deck references), `remote` (a downloaded URL in display form and its `pinned` copy), `data` (a `data:` URI), `bundled` (family, version and file basename), or `embedded` (source PPTX `part`). Acquired sources record their `format` and the acquired bytes' SHA-256; decoded source-embedded faces use the sfnt digest and original Office family/slot. A Deck-provided subset face also carries its declared `unicodeRange`. Metrics and `fsType` come from that selected face. Collection members sharing a file remain distinct.
- The Office family is legacy name ID 1, not preferred name ID 16. Legacy subfamily ID 2 and consistent `OS/2.fsSelection` / `head.macStyle` determine `regular`, `bold`, `italic` or `boldItalic`. Serialization writes this family to `a:latin`, `a:ea` and `a:cs`, and derives `b`/`i` from the Office style. This same family/style identifies the embedding slot; selection alone is not evidence of embedded payloads. See the [OpenType naming contract](https://learn.microsoft.com/en-us/typography/opentype/spec/name#name-ids).
- Authored browser weights and styles are not rewritten. Unmodified Heebo 500 emits **Heebo Medium / regular**, 700 emits **Heebo / bold**, and 800 emits **Heebo ExtraBold / regular**. No font tables are modified.
- Missing legacy family/subfamily or PostScript identity, conflicting style metadata, and unsupported legacy subfamilies produce `FONT_IDENTITY_INVALID` (error, exit 2). Variable fonts also fail explicitly: a supported exact-instance-to-Office mapping has not been established. Conversion does not silently choose the next fallback or create/replace output.
- Installed fonts, for explicit families not supplied by Deck or bundled assets, are enumerated by a pure-Node platform-directory scan with `fontkit`, cached per process. The bundled default requires no installed fonts. Installed and supplied faces follow the same default embedding requirement.
- Nothing resolves: `FONT_UNRESOLVED` (error). A generic reached before a concrete match: `FONT_GENERIC_ONLY` (error). The bundled default is never appended to explicit stacks and does not rescue an unresolved authored family.
- Per-glyph fallback is not proven to be identical in Chromium and PowerPoint. Structural Verification checks text and geometry, not selected glyph faces; the font audit below reports fallback, it does not make it portable. Supported-PowerPoint evidence remains separate.

## Bundled default

deckflip ships Liberation Sans **2.1.5**, static **Regular**, **Bold**, **Italic** and **BoldItalic** TTF faces. `FontSources`, used through `DeckFontSession`, checks each file's SHA-256 against the bundled manifest and serves those same bytes to Chromium; installed fonts, font installation and remote downloads are not required for the default.

The injected font declaration is `@layer { :root { font-family: "Liberation Sans"; } }`, in the first anonymous cascade layer before author CSS. There is no body font declaration. Authored root, body, Slide and text families, including declarations in author layers, override the inherited default. No fallback family is appended to authored stacks.

`inspect` and Conversion reports identify each selected bundled face with `asset.source: { kind: 'bundled', family: 'Liberation Sans', version: '2.1.5', file: <basename>, format: 'ttf', sha256 }`. The file is a basename, not an installation path; the hash identifies the acquired TTF bytes.

The default's exact measured faces are embedded by default, like other selected faces. Successful embedding is `fonts[].embedding.status: "embedded"` rather than a Report entry, so neither the default nor the template's explicit Arial inherently fails Strict mode. Under `--no-embed-fonts`, both receive `FONT_NOT_EMBEDDED`. Provenance lives in `asset.source.kind`.

## Deck font assets

Every stylesheet and `@font-face` source a Slide document loads goes through deckflip before Chromium sees it, so measurement and emission use one selected face.

- **Declarations.** `@font-face` rules are read from inline `<style>`, linked and `@import`ed stylesheets, local or `http(s)`, at any nesting depth (`@media`, `@supports`, `@layer`, ...). URLs resolve against the containing stylesheet's final response URL after redirects. `@import` targets are rewritten to absolute URLs because Chromium otherwise bases a fulfilled sheet on its original request URL. The redirect base is pinned with the sheet, retaining scheme, host and path only (no userinfo, query or fragment), so offline resolution is identical. A linked or imported stylesheet Chromium never requests, such as a URL with credentials, is `FONT_ASSET_UNAVAILABLE`; a `data:` stylesheet declaring `@font-face` is `FONT_ASSET_UNSUPPORTED`: its rules cannot be controlled. Imported-sheet entries name the importing stylesheet as referrer.
- **Sources.** `local()` entries are dropped, so an installed face never stands in for the supplied bytes, whatever the machine has installed. `url()` entries keep their order; an entry whose `format()` hint Chromium does not load (`embedded-opentype`, `svg`) is skipped, as Chromium skips it. A rule with only `local()` sources is `FONT_ASSET_UNSUPPORTED`.
- **Formats.** The bytes' signature decides the format, not the extension or hint. TTF, OTF and collections (face 0) are used unchanged; WOFF 1.0 and WOFF2 (google/woff2, as in Chromium) are decoded to sfnt, and Chromium is served the decoded bytes. The decoded face's SHA-256 is the asset identity; `source.sha256` records what was acquired. Anything else is `FONT_ASSET_UNSUPPORTED`. These are the formats the [#33 PowerPoint proof](https://github.com/devosurf/deckflip/issues/33) accepted once decoded.
- **Pinning.** Downloaded stylesheets and fonts are frozen into the Asset directory, `<name>.assets/fonts/<sha256>.<ext>`, and `fonts/sources.json` (schema version 1) maps each URL, by the SHA-256 of the full URL, to its copy. When a declaration loads a later source after earlier remote sources fail, those earlier failures are frozen alongside the successful pin: a recovered earlier URL cannot silently change the selected face on a repeat conversion. Failures of a declaration that never loaded a face are not frozen, so a failed conversion can recover when the network returns. A pin is never refreshed: later conversions, `validate`, `inspect` and `render` read it without the network. Delete the entry to download again; a pinned copy that is missing or was modified is `FONT_ASSET_UNAVAILABLE`. Stylesheets are requested as Chromium requests them (its User-Agent: Google Fonts serves unicode-range WOFF2 subsets to it). The per-file directory form has no Asset directory: its downloads and source failures stay in memory for one run. `--offline` still concerns only the Chromium download.
- **Failures.** A source fails only when Chromium needs the face for some text: a missing local file is `VALIDATE_MISSING_ASSET`, an unreachable or unpinned download `FONT_ASSET_UNAVAILABLE`, undecodable bytes `FONT_ASSET_UNSUPPORTED` (all errors, exit 2). A later source in the rule that loads replaces a failed one, as in Chromium. A run whose declared face did not load is not resolved to the next family in its stack. A missing local stylesheet is `VALIDATE_MISSING_ASSET`.
- **Coverage.** A face covers the code points in both its `cmap` and its declared `unicode-range`. Of the faces whose descriptors match best, the one covering most of a run's characters is selected (the later rule on a tie); a family covering none of them yields to the next family, as CSS per-character fallback does. Several subset files are never merged into one face.
- **Font audit.** After measurement, every Visible text node is resolved again and compared with Chromium's record of the platform fonts it drew the node with (`CSS.getPlatformFontsForNode`, matched by PostScript name and web-font origin). Characters the selected face lacks, or glyphs Chromium drew with any other font, are `FONT_GLYPH_FALLBACK` once per owner and face, listing the characters and Chromium's fonts. Unaccounted fallback fails the default portable requirement; under the opt-out it is a warning. This applies to installed faces too. The record names fonts, not files: it is evidence of fallback, not an asset identity.
- **Permissions.** Every selected face, including installed faces, must permit editable embedding; see the exact `fsType` contract below. deckflip checks permission bits, not the complete licence. Authors remain responsible for rights, required notices and reserved names.
- **Variable fonts** remain `FONT_IDENTITY_INVALID`; static instances are not created until an instance naming and licence policy exists.
- **Provenance.** `inspect` `fonts[]` and the Conversion report's `fonts` list each selected face once with its `asset.source`. URLs keep scheme, host and path; userinfo, query values and fragments never appear in reports, entries or pins, and the query shows as `?…`.

## Portable editable embedding

Every required used face is embedded by default. The bytes in `AcquiredFont.sfnt` are the exact decoded sfnt Chromium measured; packaging neither modifies font tables nor creates subsets. Shared selected faces reuse payload bytes and parts, with deterministic ordering. Missing assets, unsupported formats or instances, restricted permissions, uncovered text and unaccounted glyph fallback fail with exit 2 before creating or replacing the output. Text stays native: portability is never achieved by rasterising, outlining or silently substituting it.

### Package and payload

The supported contract is the isolated PowerPoint for Mac 16.114.2 [#33 proof](https://github.com/devosurf/deckflip/issues/33):

- `/ppt/fonts/fontN.fntdata` parts use `application/x-fontdata`, linked from `ppt/_rels/presentation.xml.rels` by `http://schemas.openxmlformats.org/officeDocument/2006/relationships/font`.
- `presentation.xml` sets `embedTrueTypeFonts="1"` and omits `saveSubsetFonts`. `p:embeddedFontLst` follows `p:notesSz`; each Office legacy family has one `p:embeddedFont`, with `p:regular`, `p:bold`, `p:italic` and `p:boldItalic` slots from the selected face's Office identity.
- Each new payload is **EOT 2.2** (`0x00020002`), **flags 0**: no subset, MTX compression or XOR. FontData is the unmodified complete available sfnt, TTF or CFF OTF; raw sfnt alone is not a supported font part. WOFF/WOFF2 are decoded before measurement, and those same decoded bytes are wrapped.
- The header records that face's PANOSE, weight, italic bit, `fsType`, Unicode/code-page ranges, `head.checkSumAdjustment`, and name IDs 1/2/5/4. RootString is empty and RootStringCheckSum is `0x50475342`.

### Permissions, formats and coverage

- Accept `OS/2.fsType` **0x0000** (installable) or **0x0008** (editable), optionally combined with **0x0100** (no subsetting): 0, 0x8, 0x100 and 0x108. Reject **0x0002** (restricted), **0x0004** (preview & print), any **0x0200** (bitmap only), and unsupported permission-bit combinations with `FONT_EMBED_RESTRICTED`.
- `fsType` is the only licence signal deckflip checks. It is necessary, not sufficient: the author must obtain embedding rights and comply with required notices and reserved names. Report provenance and `fsType` identify the selected source; they are not a legal clearance.
- Collections (TTC/dfont members) fail `FONT_EMBED_FORMAT`: extracting a member has no supported-PowerPoint proof. Supply a complete standalone static TTF/OTF, or its WOFF/WOFF2 encoding. Variable faces remain `FONT_IDENTITY_INVALID`; creating and naming derived instances is unsupported.
- Embed the complete **available** character set, not only current Slide text. A downloaded `unicode-range` web subset is not a full family. If its `cmap` covers all characters the Slides use, embed it and emit `FONT_EMBED_SUBSET` (warning) with the declared covered ranges and limited-edit status.
- One Office family/style slot holds one asset. Subset assets are never merged. When competing subsets need the same slot, characters left uncovered fail `FONT_EMBED_COVERAGE`, which lists them and points to supplying the complete font. A subset does not become complete by covering current Slide text.

### Opt-out, validation and reporting

`--no-embed-fonts` is the sole explicit machine-dependent opt-out for **new HTML -> PPTX embedding**; the library option is `embedFonts: false`. Each selected face not supplied by a preserved source embedding gets `FONT_NOT_EMBEDDED` (warning), saying recipients need that exact face installed. Portability-only `FONT_EMBED_RESTRICTED`, `FONT_EMBED_FORMAT`, `FONT_EMBED_COVERAGE` and `FONT_GLYPH_FALLBACK` failures become warnings in this mode. Identity, missing-asset and other authoring validation errors keep their existing precedence. Source embedded parts are always preserved, including under this opt-out.

The old opt-in/name-list option and unsupported/safe-font report codes are retired. A family-name whitelist never establishes portability, including for Arial or Office-bundled fonts.

`fonts[].embedding` records `status: "embedded" | "eligible" | "not-embedded" | "preserved"`, optional package `part`, and `subset` / `compressed` flags. Successful new packaging changes status to `embedded` without an informational Report entry, so a clean strict Deck stays clean. `validate` reports eligibility/requested behavior as `eligible`, never completed embedding. Selection-only inspection is not proof of packaged bytes.

Structural Verification does not establish font fidelity. Package inspection plus supported-PowerPoint edit/additional-character/save/reopen evidence with source fonts unavailable remain required; do not alter the developer's fonts or Office cache to simulate isolation. Cached Office cloud faces can override embedded fonts, and AppleScript PDF export can clear the embed setting before a later save. Existing layout corpus fixtures explicitly opt out to retain their byte-bound Oracle records; the embedding fixture requires its own isolated-host record.

## PPTX -> HTML

- Every `typeface` becomes `font-family: "<typeface>", <generic>` where the generic comes from the font's `OS/2` family class / panose when the file is available, else from the theme slot (`+mj-lt` -> major font of the theme). Theme fonts are resolved to their concrete names and also exposed as `--theme-major-font`/`--theme-minor-font`.
- No bundled default is emitted: text styles already name the explicit source PPTX family.
- Preserve existing embedded font payloads, relationships, rights and Office identity through supported round trips, even when `embedFonts: false` disables new embedding. `embeddedFonts[]` records source-part family, Office slot, part, relationship ID, `kind` (`complete`, `subset`, `mtx` or `xor`), optional decoded sfnt `sha256`, version, flags, `fsType`, subset/compression and source name metadata. Its `embedding.status: "preserved"` identifies copied source parts, not newly embedded sfnt faces. EOT subset flag `0x1` means limited editing and is reported as `FONT_EMBED_SUBSET`.
- Uncompressed non-XOR source EOT can expose its sfnt through extracted `@font-face` assets; its `sha256` hashes those decoded sfnt bytes, not the EOT wrapper. PowerPoint-written MTX remains verbatim in `source.pptx`; unavailable HTML preview decoding reports `FONT_EMBED_FORMAT` (warning) rather than claiming measured identity from compressed bytes. `embeddedFonts[]` is separate from `fonts[]`: an opaque preserved payload has no decoded sfnt digest. `kind` prioritizes MTX over XOR over subset when flags overlap; the original flags remain available.
- PPTX-input `convert` and `validate` do not run new-embedding eligibility checks or emit `FONT_NOT_EMBEDDED`. Existing source permission and format limitations are warnings, never blockers to preservation. Explicit CLI `--no-embed-fonts` with PPTX input is an invocation error (exit 3); the flag controls only new HTML -> PPTX embedding.
- Editing text does not expand a preserved subset or decode an opaque MTX payload. Edited text using either receives `FONT_EMBED_SUBSET` (warning): coverage cannot be verified and new characters may fall back. Opaque MTX also retains its source `FONT_EMBED_FORMAT` preview-decoding warning. Characters added outside a preserved subset may fall back to another installed font. Preserve the original payload and Office slot rather than replacing it with a newly selected face or blocking the round trip.
- Fonts the authoring machine lacks and the source did not embed are `FONT_MISSING_FOR_LAYOUT` (warning): the HTML declares the original name (so the round-trip writes it back) but Chromium measured with the next entry in the stack; `render` of the HTML will differ from PowerPoint.

## What the skill tells the agent

1. Name a concrete family or inherit the bundled default; never rely on a generic alone. Authored CSS weights remain intact.
2. Default conversion embeds each measured face, including installed faces and bundled Liberation Sans. Check `fonts[].embedding`; a clean report or selected family name alone is not package evidence.
3. Supply complete supported static fonts with editable embedding rights. Fix `FONT_EMBED_RESTRICTED`, `FONT_EMBED_FORMAT`, `FONT_EMBED_COVERAGE` and glyph fallback rather than changing weights, outlining or rasterising text.
4. Keep pinned hosted assets with the Deck for repeatable offline conversion. A reported web subset remains limited-edit even when current Slide text is covered.
5. Use `--no-embed-fonts` only for intentional machine-dependent new HTML -> PPTX output; selected faces without preserved embeddings then report that recipients need them installed. Source embedded fonts always survive supported round trips. Inspect selected asset provenance and permission bits; authors remain responsible for licence compliance.
