# The font Chromium measured with is the font written; generic families are rejected

The `font-family` stack is resolved on the authoring machine to the first deck-provided or installed family, that single name is written to the PPTX, and `validate` fails when nothing resolves or when a generic family (`sans-serif`, `system-ui`, ...) is the first match. A PPTX whose text was wrapped with one font and labelled with another is wrong on every viewer, and generic families resolve to different faces per OS, so the same deck would convert differently on two machines. The strictness is unusual for an HTML tool and will surprise authors used to `font-family: sans-serif` working; the injected base stylesheet (`body { font-family: Arial }`) keeps unstyled text deterministic and the error hint names the safe set.
