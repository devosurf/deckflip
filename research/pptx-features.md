# Question

For each PPTX feature class — charts, SmartArt, embedded audio/video, speaker notes, slide masters/layouts/themes, sections, comments, hyperlinks, grouped shapes, placeholders, VBA/macros — how is it stored in the OPC package, and is a faithful HTML representation feasible or must it be preserved as an opaque blob?

# Findings

## Bottom line

- `Feasible as HTML or HTML+metadata`: embedded audio/video, speaker notes, slide masters/layouts/themes, sections, comments, hyperlinks, grouped shapes, placeholders.
- `Renderable in HTML, but preserve the original PPTX parts as source state for round-trip fidelity`: classic charts and SmartArt; ChartEx/extended charts are separate Office extension parts and should be treated as best-effort/opaque if encountered.
- `Opaque binary preservation required`: VBA/macros.

## Charts

- The core chart lives in `ppt/charts/chartN.xml` as `ChartPart`, with content type `application/vnd.openxmlformats-officedocument.drawingml.chart+xml` and relationship type `http://schemas.openxmlformats.org/officeDocument/2006/relationships/chart`. The Open XML SDK source also shows the chart part can have sibling `ChartStylePart` and `ChartColorStylePart` children, and may carry an embedded workbook via `EmbeddedPackagePart`. `ChartStylePart` is `application/vnd.ms-office.chartstyle+xml` / `http://schemas.microsoft.com/office/2011/relationships/chartStyle`; `ChartColorStylePart` is `application/vnd.ms-office.chartcolorstyle+xml` / `http://schemas.microsoft.com/office/2011/relationships/chartColorStyle`. The embedded workbook is reached through `externalData` with a `package` relationship. Sources: https://raw.githubusercontent.com/dotnet/Open-XML-SDK/main/generated/DocumentFormat.OpenXml/DocumentFormat.OpenXml.Generator/DocumentFormat.OpenXml.Generator.OpenXmlGenerator/Part_ChartPart.g.cs, https://raw.githubusercontent.com/dotnet/Open-XML-SDK/main/generated/DocumentFormat.OpenXml/DocumentFormat.OpenXml.Generator/DocumentFormat.OpenXml.Generator.OpenXmlGenerator/Part_ChartStylePart.g.cs, https://raw.githubusercontent.com/dotnet/Open-XML-SDK/main/generated/DocumentFormat.OpenXml/DocumentFormat.OpenXml.Generator/DocumentFormat.OpenXml.Generator.OpenXmlGenerator/Part_ChartColorStylePart.g.cs, https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/d87be363-04a9-48a0-a574-80daadcecdac
- Assessment: classic chart rendering in HTML/SVG/Canvas is feasible, but a plain HTML subtree is not a faithful PowerPoint chart model. For round-trip fidelity, preserve the chart XML plus any embedded workbook and style/color sibling parts as source state; HTML should be treated as the rendering/view layer, not the authoritative model. PowerPoint's ChartEx extension is separate and best treated as best-effort/opaque. [Inference grounded in the package structure above.]

## SmartArt

- SmartArt is not a single part. In PresentationML it is a `p:graphicFrame` whose `a:graphicData` points to diagram relationships via `dgm:relIds` (`r:dm`, `r:lo`, `r:qs`, `r:cs`). The package normally contains sibling parts under `ppt/diagrams/`: `dataN.xml` (`DiagramDataPart`, `application/vnd.openxmlformats-officedocument.drawingml.diagramData+xml`, `http://schemas.openxmlformats.org/officeDocument/2006/relationships/diagramData`), `layoutN.xml` (`DiagramLayoutDefinitionPart`, `application/vnd.openxmlformats-officedocument.drawingml.diagramLayout+xml`, `.../diagramLayout`), `colorsN.xml` (`DiagramColorsPart`, `application/vnd.openxmlformats-officedocument.drawingml.diagramColors+xml`, `.../diagramColors`), `quickStyleN.xml` (`DiagramStylePart`, `application/vnd.openxmlformats-officedocument.drawingml.diagramStyle+xml`, `.../diagramQuickStyle`), and often a persisted drawing/cache part `drawingN.xml` (`DiagramPersistLayoutPart`, `application/vnd.ms-office.drawingml.diagramDrawing+xml`, `http://schemas.microsoft.com/office/2007/relationships/diagramDrawing`). Microsoft describes the diagram layout cache as the last successful output of the diagram layout, and notes it does not capture all text formatting; the final formatting is derived from the semantic data plus the layout definition. Sources: https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/a76a4974-881b-4ca5-98fe-a758cda15e82, https://learn.microsoft.com/en-us/openspecs/office_standards/ms-odrawxml/c36c1152-3aec-45e5-8f16-936da2678e5d, https://learn.microsoft.com/en-us/openspecs/office_standards/ms-odrawxml/44da4385-43e1-4c9e-9061-71557d17155a, https://raw.githubusercontent.com/dotnet/Open-XML-SDK/main/generated/DocumentFormat.OpenXml/DocumentFormat.OpenXml.Generator/DocumentFormat.OpenXml.Generator.OpenXmlGenerator/Part_DiagramDataPart.g.cs, https://raw.githubusercontent.com/dotnet/Open-XML-SDK/main/generated/DocumentFormat.OpenXml/DocumentFormat.OpenXml.Generator/DocumentFormat.OpenXml.Generator.OpenXmlGenerator/Part_DiagramLayoutDefinitionPart.g.cs, https://raw.githubusercontent.com/dotnet/Open-XML-SDK/main/generated/DocumentFormat.OpenXml/DocumentFormat.OpenXml.Generator/DocumentFormat.OpenXml.Generator.OpenXmlGenerator/Part_DiagramColorsPart.g.cs, https://raw.githubusercontent.com/dotnet/Open-XML-SDK/main/generated/DocumentFormat.OpenXml/DocumentFormat.OpenXml.Generator/DocumentFormat.OpenXml.Generator.OpenXmlGenerator/Part_DiagramStylePart.g.cs, https://raw.githubusercontent.com/dotnet/Open-XML-SDK/main/generated/DocumentFormat.OpenXml/DocumentFormat.OpenXml.Generator/DocumentFormat.OpenXml.Generator.OpenXmlGenerator/Part_DiagramPersistLayoutPart.g.cs
- Assessment: a faithful *rendering* in HTML is feasible if we use the cached/persisted geometry as the visual source. But editable round-trip is not faithful unless we preserve the full SmartArt bundle atomically, because the layout is algorithmic and the cache is only the last rendered output. Recommendation: preserve the original diagram parts as source state, and render HTML from the cached drawing shape tree.

## Embedded audio/video

- Media is stored as a binary Media Part under `ppt/media/mediaN.ext` (for example `media1.mp4`). The content type is the media file’s MIME type; [MS-PPTX] says it may be any supported audio or video type. The source relationship type is `http://schemas.microsoft.com/office/2007/relationships/media`, and the part must be the target of an explicit relationship from a Slide, Slide Layout, or Slide Master. The slide XML can reference media with `a:videoFile` / `a:audioFile`, and newer PowerPoint markup can use `p14:media` with `r:embed` to point at the embedded media part. Sources: https://learn.microsoft.com/en-us/openspecs/office_standards/ms-pptx/922b7818-6e5f-4641-a9c5-fab4063ec124, https://learn.microsoft.com/en-us/office/open-xml/presentation/how-to-add-an-audio-to-a-slide-in-a-presentation, https://raw.githubusercontent.com/dotnet/Open-XML-SDK/main/generated/DocumentFormat.OpenXml/DocumentFormat.OpenXml.Generator/DocumentFormat.OpenXml.Generator.OpenXmlGenerator/Part_SlideLayoutPart.g.cs, https://raw.githubusercontent.com/dotnet/Open-XML-SDK/main/generated/DocumentFormat.OpenXml/DocumentFormat.OpenXml.Generator/DocumentFormat.OpenXml.Generator.OpenXmlGenerator/Part_SlideMasterPart.g.cs, https://raw.githubusercontent.com/dotnet/Open-XML-SDK/main/generated/DocumentFormat.OpenXml/DocumentFormat.OpenXml.Generator/DocumentFormat.OpenXml.Generator.OpenXmlGenerator/Part_NotesSlidePart.g.cs
- Assessment: feasible in HTML. Use `<audio>` / `<video>` for the media itself and preserve the binary asset; poster/preview imagery maps to ordinary image assets. The part is not an opaque blob requirement for the feature as a whole.

## Speaker notes

- Speaker notes live in `ppt/notesSlides/notesSlideN.xml` as `NotesSlidePart`, content type `application/vnd.openxmlformats-officedocument.presentationml.notesSlide+xml`, relationship type `http://schemas.openxmlformats.org/officeDocument/2006/relationships/notesSlide`. A slide with notes has an implicit relationship to one Notes Slide part. The notes page itself contains a normal shape tree, and the note text is just ordinary DrawingML text inside a body placeholder. The Notes Master is separate: `ppt/notesMasters/notesMasterN.xml` as `NotesMasterPart`, content type `application/vnd.openxmlformats-officedocument.presentationml.notesMaster+xml`, relationship type `http://schemas.openxmlformats.org/officeDocument/2006/relationships/notesMaster`. Sources: https://learn.microsoft.com/en-us/office/open-xml/presentation/working-with-notes-slides, https://learn.microsoft.com/en-us/office/open-xml/presentation/structure-of-a-presentationml-document, https://raw.githubusercontent.com/dotnet/Open-XML-SDK/main/generated/DocumentFormat.OpenXml/DocumentFormat.OpenXml.Generator/DocumentFormat.OpenXml.Generator.OpenXmlGenerator/Part_NotesSlidePart.g.cs, https://raw.githubusercontent.com/dotnet/Open-XML-SDK/main/generated/DocumentFormat.OpenXml/DocumentFormat.OpenXml.Generator/DocumentFormat.OpenXml.Generator.OpenXmlGenerator/Part_NotesMasterPart.g.cs
- Assessment: feasible in HTML as a notes panel or sidecar document. The content is plain rich text and inherited placeholder structure, not an opaque binary.

## Slide masters / layouts / themes

- `ppt/presentation.xml` is the `PresentationPart` root. It carries the slide-master list, slide list, notes-master list, and other presentation-wide metadata. `ppt/slideMasters/slideMasterN.xml` is `SlideMasterPart`, content type `application/vnd.openxmlformats-officedocument.presentationml.slideMaster+xml`, relationship type `http://schemas.openxmlformats.org/officeDocument/2006/relationships/slideMaster`; it owns `cSld`, `txStyles`, `sldLayoutIdLst`, etc. `ppt/slideLayouts/slideLayoutN.xml` is `SlideLayoutPart`, content type `application/vnd.openxmlformats-officedocument.presentationml.slideLayout+xml`, relationship type `http://schemas.openxmlformats.org/officeDocument/2006/relationships/slideLayout`; it is associated with a slide master and may carry a theme override. `ppt/theme/themeN.xml` is `ThemePart`, content type `application/vnd.openxmlformats-officedocument.theme+xml`, relationship type `http://schemas.openxmlformats.org/officeDocument/2006/relationships/theme`. Sources: https://learn.microsoft.com/en-us/office/open-xml/presentation/structure-of-a-presentationml-document, https://learn.microsoft.com/en-us/office/open-xml/presentation/working-with-presentations, https://learn.microsoft.com/en-us/office/open-xml/presentation/working-with-slide-masters, https://raw.githubusercontent.com/dotnet/Open-XML-SDK/main/generated/DocumentFormat.OpenXml/DocumentFormat.OpenXml.Generator/DocumentFormat.OpenXml.Generator.OpenXmlGenerator/Part_PresentationPart.g.cs, https://raw.githubusercontent.com/dotnet/Open-XML-SDK/main/generated/DocumentFormat.OpenXml/DocumentFormat.OpenXml.Generator/DocumentFormat.OpenXml.Generator.OpenXmlGenerator/Part_SlideMasterPart.g.cs, https://raw.githubusercontent.com/dotnet/Open-XML-SDK/main/generated/DocumentFormat.OpenXml/DocumentFormat.OpenXml.Generator/DocumentFormat.OpenXml.Generator.OpenXmlGenerator/Part_SlideLayoutPart.g.cs, https://raw.githubusercontent.com/dotnet/Open-XML-SDK/main/generated/DocumentFormat.OpenXml/DocumentFormat.OpenXml.Generator/DocumentFormat.OpenXml.Generator.OpenXmlGenerator/Part_ThemePart.g.cs
- Assessment: feasible as deck-level template/theme metadata and CSS variables. Keep the relationship graph and placeholder ids if exact inheritance needs to round-trip, but no opaque blob is required.

## Sections

- Sections are not a separate package part. PowerPoint stores them as a `p14:sectionLst` extension inside `ppt/presentation.xml` (`<p:extLst><p:ext uri="{521415D9-36F7-43E2-AB2F-B90AF26B5E84}"><p14:sectionLst>...`). The `CT_SectionList` element lives in the PowerPoint 2010 namespace (`http://schemas.microsoft.com/office/powerpoint/2010/main`) and sections are defined by names/ids plus slide-id lists. Sources: https://learn.microsoft.com/en-us/openspecs/office_standards/ms-pptx/db88eca9-e5d0-4fc6-b1c9-5387557998bd, https://learn.microsoft.com/en-us/openspecs/office_standards/ms-pptx/5bd8a237-8753-4d05-b757-c5e84e5d1ba6, https://learn.microsoft.com/en-us/openspecs/office_standards/ms-pptx/1f21a089-944d-410b-bd47-4f5e692c2532, https://learn.microsoft.com/en-us/office/open-xml/presentation/structure-of-a-presentationml-document
- Assessment: feasible as deck outline/grouping metadata. No opaque blob is needed.

## Comments

- Classic PresentationML comments are stored as `ppt/comments/commentN.xml` (`SlideCommentsPart` / `CommentList`) with content type `application/vnd.openxmlformats-officedocument.presentationml.comments+xml` and relationship type `http://schemas.openxmlformats.org/officeDocument/2006/relationships/comments`. Comment authors are stored separately in `ppt/commentAuthors.xml` (`CommentAuthorsPart` / `CommentAuthorList`) with content type `application/vnd.openxmlformats-officedocument.presentationml.commentAuthors+xml` and relationship type `http://schemas.openxmlformats.org/officeDocument/2006/relationships/commentAuthors`. `p:cm` carries authorId, dt, idx, pos, and text. Sources: https://learn.microsoft.com/en-us/office/open-xml/presentation/working-with-comments, https://learn.microsoft.com/en-us/office/open-xml/presentation/structure-of-a-presentationml-document, https://raw.githubusercontent.com/dotnet/Open-XML-SDK/main/generated/DocumentFormat.OpenXml/DocumentFormat.OpenXml.Generator/DocumentFormat.OpenXml.Generator.OpenXmlGenerator/Part_SlideCommentsPart.g.cs, https://raw.githubusercontent.com/dotnet/Open-XML-SDK/main/generated/DocumentFormat.OpenXml/DocumentFormat.OpenXml.Generator/DocumentFormat.OpenXml.Generator.OpenXmlGenerator/Part_CommentAuthorsPart.g.cs
- Modern PowerPoint comments are an Office extension: `application/vnd.ms-powerpoint.comments+xml` with relationship type `http://schemas.microsoft.com/office/2018/10/relationships/comments` (slide-scoped). If they appear in the package, preserve them as extension metadata rather than normalizing them away. Sources: https://learn.microsoft.com/en-us/openspecs/office_standards/ms-pptx/b85a9293-bdca-4c6b-a554-8f3918db9791, https://learn.microsoft.com/en-us/openspecs/office_standards/ms-pptx/c0f70c68-e456-452b-b6fe-6ff6bc36bd90, https://raw.githubusercontent.com/dotnet/Open-XML-SDK/main/generated/DocumentFormat.OpenXml/DocumentFormat.OpenXml.Generator/DocumentFormat.OpenXml.Generator.OpenXmlGenerator/Part_PresentationPart.g.cs
- Assessment: feasible as HTML annotations / an in-page notes drawer. Comments are not canvas content, so they do not need rasterization or opaque blob preservation.

## Hyperlinks

- Ordinary hyperlinks are not separate package parts. They are relationships from a slide part (or text/shape XML) to an external URI, with relationship type `http://schemas.openxmlformats.org/officeDocument/2006/relationships/hyperlink` and `TargetMode="External"`. The hyperlink is referenced from XML using `a:hlinkClick/@r:id` or `a:hlinkHover/@r:id`. Internal slide jumps are also relationship-driven; `hlinkClick` supports `ppaction://hlinksldjump` for jumping within the deck, and `ppaction://macro?name=...` is a separate macro action, not a normal hyperlink. Sources: https://learn.microsoft.com/en-us/office/open-xml/presentation/how-to-get-all-the-external-hyperlinks-in-a-presentation, https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/7ff3db24-b7b9-4ffe-aa78-3ec47cab2489
- Assessment: directly feasible as HTML `<a href>` / fragment links. No opaque preservation needed.

## Grouped shapes

- A group shape is inline XML, not its own part. It is `p:grpSp` inside the slide/master/layout/notes shape tree, with `p:grpSpPr` carrying the group transform (`a:off`, `a:ext`, `a:chOff`, `a:chExt`). Children remain ordinary shapes, pictures, connectors, graphic frames, or nested groups. Relationships belong to the containing part, not the group itself. Sources: https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.groupshape?view=openxml-3.0.1, https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/7ff3db24-b7b9-4ffe-aa78-3ec47cab2489, https://learn.microsoft.com/en-us/office/open-xml/presentation/structure-of-a-presentationml-document
- Assessment: feasible in HTML as nested positioned containers / transform groups. No opaque blob is required.

## Placeholders

- A placeholder is an ordinary shape with `p:ph` in its non-visual properties. The placeholder index (`idx`) is what PowerPoint uses to match a slide placeholder to its corresponding layout/master placeholder; the placeholder type (`type`) says what kind of content the slot is intended to contain. Placeholders can appear on slides, layouts, masters, notes slides, and notes masters. Sources: https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.placeholdershape?view=openxml-3.0.1, https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/8b5c01b6-a623-4952-a8ab-e6a5177e47ec, https://learn.microsoft.com/en-us/office/open-xml/presentation/working-with-slide-masters, https://learn.microsoft.com/en-us/office/open-xml/presentation/working-with-notes-slides
- Assessment: feasible as semantic HTML placeholders with data attributes / template slots. No opaque blob is required.

## VBA / macros

- A VBA project is stored as `ppt/vbaProject.bin` (`VbaProjectPart`) with content type `application/vnd.ms-office.vbaProject` and relationship type `http://schemas.microsoft.com/office/2006/relationships/vbaProject`. A package may contain at most one VBA Project part, targeted by an implicit relationship from the presentation part. The presentation’s macro-enabled main content type is `application/vnd.ms-powerpoint.presentation.macroEnabled.main+xml` (`.pptm`). The `hlinkClick` action `ppaction://macro?name=...` is how slide XML can invoke a macro. Sources: https://learn.microsoft.com/en-us/openspecs/office_standards/ms-offmacro2/6205a8c4-f957-47ed-a64b-fae5ea96c5a0, https://learn.microsoft.com/en-us/openspecs/office_standards/ms-offmacro2/18138244-588d-4c8f-bd82-1b9a4aa2af38, https://raw.githubusercontent.com/dotnet/Open-XML-SDK/main/generated/DocumentFormat.OpenXml/DocumentFormat.OpenXml.Generator/DocumentFormat.OpenXml.Generator.OpenXmlGenerator/Part_VbaProjectPart.g.cs, https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/7ff3db24-b7b9-4ffe-aa78-3ec47cab2489
- Assessment: opaque binary preservation required. HTML cannot faithfully execute or represent VBA/macros; keep the binary project intact and make macro-triggering actions inert in the HTML view.

# Recommendation

Use a hybrid policy:

1. Preserve charts and SmartArt as first-class source state in sidecar/part-bundle form, and render them in HTML from that preserved state.
2. Map media, notes, comments, masters/layouts/themes, sections, hyperlinks, grouped shapes, and placeholders to native HTML/CSS/metadata structures.
3. Preserve `vbaProject.bin` verbatim and treat macro actions as non-executable metadata in HTML.

That matches the repo’s native-first rule without pretending HTML has native equivalents for chart/diagram or macro semantics.

# Open questions

1. For comments, do we want to normalize everything to the classic ECMA-376 comment model, or preserve both classic and modern PowerPoint comments separately?
2. For charts and SmartArt, do we want a custom HTML component model with hidden source-state sidecars, or a pure render-only view plus opaque pass-through of the original OOXML bundle?
3. For embedded media, should linked media stay linked in HTML, or should we always copy it into the output package/assets folder?
