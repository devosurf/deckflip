# Question

What can render a PPTX to images headlessly for visual comparison against Chromium screenshots, how faithful is each option to real PowerPoint, and which image-comparison tooling gives a usable threshold?

# Findings

## LibreOffice / soffice headless

- LibreOffice supports `--headless` to run without a UI, and `--convert-to` to export via a named graphics filter with JSON-style export parameters. The graphics-export docs list `impress_png_Export` as the PNG filter for Impress presentations, and the available export properties include `PixelWidth`, `PixelHeight`, `PageNumber`, and `AntiAliasing`. Sources: https://help.libreoffice.org/latest/en-GB/text/shared/guide/start_parameters.html, https://help.libreoffice.org/latest/en-GB/text/shared/guide/graphic_export_params.html
- LibreOffice’s own compatibility docs warn that PPTX conversion is not one-to-one: complex Microsoft Office documents may need manual reformatting, and the PowerPoint-specific trouble spots called out are AutoShapes, tab/line/paragraph spacing, master background graphics, grouped objects, and certain multimedia effects. Source: https://help.libreoffice.org/latest/en-US/text/shared/guide/ms_import_export_limitations.html?DbPAR=WRITER&System=WIN
- For whole-deck rasterization, the practical LibreOffice path is PPTX → PDF → page images: the official PDF export filter (`impress_pdf_Export`) exports all slides, while the official PNG export filter is a single-selection export (`EXPORT ALIEN SUPPORTSSELECTION`) and the upstream bug for multi-slide bitmap export is still open. Sources: https://help.libreoffice.org/latest/en-US/text/shared/guide/convertfilters.html, https://help.libreoffice.org/latest/en-US/text/shared/guide/pdf_params.html, https://api.libreoffice.org/docs/idl/ref/servicecom_1_1sun_1_1star_1_1drawing_1_1GraphicExportFilter.html, https://bugs.documentfoundation.org/rest/bug/48015, https://bugs.documentfoundation.org/rest/bug/67614
- If you need per-slide PNGs from inside LibreOffice rather than from the CLI, the UNO `com.sun.star.drawing.GraphicExportFilter` service is explicitly documented as exporting pages, shapes, or groups from a drawing document; the export flow is `setSourceDocument()` followed by `filter()`. Source: https://api.libreoffice.org/docs/idl/ref/servicecom_1_1sun_1_1star_1_1drawing_1_1GraphicExportFilter.html
- LibreOffice requires write access to a user profile directory, and the CLI docs document `-env:VAR[=VALUE]` bootstrap variables, which is the mechanism to isolate per-job profiles when you run multiple conversions concurrently. Source: https://help.libreoffice.org/latest/en-GB/text/shared/guide/start_parameters.html
- Additional LibreOffice fidelity risks are documented by The Document Foundation itself: newer OOXML chart types such as box-and-whisker, funnel, Pareto, sunburst, treemap, and waterfall cannot yet be rendered or edited in LibreOffice 26.8; region-map charts lose geographic data; and TDF’s PowerPoint support notes call out gradients/transparency, custom shapes, SmartArt, shadows, WordArt/Fontwork 3D, chart backgrounds, hyperlink colors, and master-based text-box placement as historically bug-prone areas. Sources: https://blog.documentfoundation.org/blog/2026/08/26/libreoffice-26-8/, https://blog.documentfoundation.org/blog/2021/05/08/improvements-in-libreoffices-powerpoint-presentation-support-3/
- Font substitution is display-time-only and host-dependent: LibreOffice’s font substitution docs say a replacement font changes rendering only and does not alter the saved font settings. That means identical PPTX input can rasterize differently across machines unless you pin/install/embed the exact font set. Source: https://help.libreoffice.org/latest/en-US/text/shared/optionen/01010700.html

## PowerPoint automation on macOS and Windows

- Microsoft’s PowerPoint VBA object model includes `Application`, `Presentations`, `Presentation`, `Slides`, `Slide`, `Shapes`, and more. The `Application` object example shows `New PowerPoint.Application` and `Presentations.Open`, which is the Windows COM/OLE automation pattern. Sources: https://learn.microsoft.com/en-us/office/vba/api/overview/powerpoint/object-model, https://learn.microsoft.com/en-us/office/vba/api/powerpoint.application
- PowerPoint has first-party export methods for images: `Presentation.Export` exports each slide in a presentation to a folder using a graphics filter; `Slide.Export` exports one slide to a file; both support `ScaleWidth` and `ScaleHeight` in pixels. `ExportAsFixedFormat` produces a static PDF/XPS. Sources: https://learn.microsoft.com/en-us/office/vba/api/powerpoint.presentation.export, https://learn.microsoft.com/en-au/office/vba/api/powerpoint.slide.export, https://learn.microsoft.com/en-us/office/vba/api/PowerPoint.Presentation.ExportAsFixedFormat
- Microsoft also documents `Presentation.SaveAs` with `PpSaveAsFileType` constants including `ppSaveAsPNG`, `ppSaveAsJPG`, `ppSaveAsPDF`, and `ppSaveAsXPS`, so PowerPoint itself can emit the raster or PDF artifacts you would use as comparison baselines. Source: https://learn.microsoft.com/en-us/office/vba/api/powerpoint.ppsaveasfiletype
- Microsoft explicitly says Office is not recommended or supported for unattended, non-interactive, server-side automation. The support article says Office apps assume an interactive desktop and user profile, can deadlock on modal dialogs, are non-reentrant, and are not designed for server-side use. Microsoft’s newer unattended-RPA article repeats the same warning and labels the unattended configuration “AS IS”. Sources: https://support.microsoft.com/en-us/topic/considerations-for-server-side-automation-of-office-48bcfe93-8a89-47f1-0bce-017433ad79e2, https://learn.microsoft.com/en-us/office/client-developer/integration/considerations-unattended-automation-office-microsoft-365-for-unattended-rpa
- On Mac, Microsoft documents that Office for Mac is sandboxed, which affects file access and cross-process communication. The documented Mac bridge is `AppleScriptTask`, which calls an external AppleScript file from VBA; `MacScript` is deprecated. Sources: https://learn.microsoft.com/en-us/office/vba/api/overview/office-mac, https://learn.microsoft.com/en-gb/office/vba/office-mac/applescripttask
- Microsoft’s Mac VBA docs say most of the Office-for-Windows VBA object model is available on Mac, but the supported Mac-specific automation bridge is still VBA plus `AppleScriptTask`, not a server-side automation model. Source: https://learn.microsoft.com/en-us/office/vba/api/overview/office-mac
- Apple’s own platform docs add two practical Mac constraints: Apple Events permission is interactive/TCC-gated, and system-context launch daemons do not have access to the window server. In practice that means a Mac automation host needs a logged-in Aqua/WindowServer session; a pure daemon cannot drive PowerPoint. Sources: https://developer.apple.com/documentation/bundleresources/information-property-list/nsappleeventsusagedescription, https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/DesigningDaemons.html

## Other viable renderer

- Aspose.Slides is a commercial SDK that can render individual slides or all slides to PNG/JPEG/GIF/TIFF and other image formats. The docs show `Slide.get_image()` / `ISlide.GetImage()` for per-slide rendering, custom pixel sizes, notes/comments layouting, and TIFF options. Sources: https://docs.aspose.com/slides/python-net/convert-slide/, https://docs.aspose.com/slides/net/convert-powerpoint-to-png/
- Aspose’s docs also say slide images are static and do not export animations, and that evaluation mode adds a watermark. Source: https://docs.aspose.com/slides/python-net/convert-slide/, https://docs.aspose.com/slides/net/convert-powerpoint-to-png/

## Image-comparison tooling for Chromium screenshots

- `odiff` is the strongest primary comparator I found for CI: it is a native SIMD image-diff tool, compares visual differences with a `threshold` in the 0–1 range, supports anti-aliasing detection, ignore regions, diff overlays, and a persistent server mode (`ODiffServer` / `--server`) to amortize spawn cost across many comparisons. It also returns both `diffCount` and `diffPercentage`. Source: https://raw.githubusercontent.com/dmtrKovalenko/odiff/main/README.md
- `pixelmatch` is the best pure-JS fallback/debugging tool: it is a small, dependency-free pixel-level image-comparison library with anti-aliased pixel detection, perceptual color-difference metrics, thresholding in the 0–1 range, and diff-image output. It requires equal image dimensions. Source: https://raw.githubusercontent.com/mapbox/pixelmatch/main/README.md
- `ssim.js` returns a similarity score from 0 to 1 rather than a diff count, which makes it less useful as the primary pass/fail gate for slide screenshots. Its README and source also show that it converts images to grayscale before scoring and downsamples by default when the image is larger than `maxSize` 256, so it can miss small color-only or fine-detail regressions unless reconfigured. Sources: https://raw.githubusercontent.com/obartra/ssim/master/README.md, https://raw.githubusercontent.com/obartra/ssim/master/src/index.ts, https://raw.githubusercontent.com/obartra/ssim/master/src/defaults.ts, https://raw.githubusercontent.com/obartra/ssim/master/src/downsample.ts

# Recommendation

Use a two-layer rendering strategy and a single primary comparator:

1. **Primary automated CI renderer:** LibreOffice headless, but via the PDF route: `soffice --headless --convert-to 'pdf:impress_pdf_Export'` and then rasterize the PDF pages to PNG with a fixed DPI. Use UNO `GraphicExportFilter` only when you need per-slide export inside LibreOffice itself. This keeps the pipeline fully local and scriptable, while avoiding the direct-PNG single-slide limitation. Sources: https://help.libreoffice.org/latest/en-US/text/shared/guide/convertfilters.html, https://help.libreoffice.org/latest/en-US/text/shared/guide/pdf_params.html, https://api.libreoffice.org/docs/idl/ref/servicecom_1_1sun_1_1star_1_1drawing_1_1GraphicExportFilter.html, https://bugs.documentfoundation.org/rest/bug/48015
2. **Ground-truth / calibration renderer:** real PowerPoint export on a dedicated Windows or Mac runner, using `Presentation.Export`, `Slide.Export`, or `SaveAs(..., ppSaveAsPNG/ppSaveAsPDF)` to generate images/PDF. This is the closest-to-PowerPoint option by definition, but Microsoft explicitly disallows treating Office as an unattended server component, so keep it as an oracle or calibration path rather than the default CI service. Sources: https://learn.microsoft.com/en-us/office/vba/api/powerpoint.presentation.export, https://learn.microsoft.com/en-au/office/vba/api/powerpoint.slide.export, https://learn.microsoft.com/en-us/office/vba/api/powerpoint.ppsaveasfiletype, https://support.microsoft.com/en-us/topic/considerations-for-server-side-automation-of-office-48bcfe93-8a89-47f1-0bce-017433ad79e2
3. **Comparator:** `odiff` as the primary pass/fail gate, with `threshold` starting at the documented default of `0.1`, `antialiasing` enabled, and `ignoreRegions` for known noisy areas. Use `pixelmatch` only when you want a pure-JS fallback or a diff image in-process. Avoid `ssim.js` as the main gate; it is better suited as a supplemental similarity score, not as the decision metric. Sources: https://raw.githubusercontent.com/dmtrKovalenko/odiff/main/README.md, https://raw.githubusercontent.com/mapbox/pixelmatch/main/README.md, https://raw.githubusercontent.com/obartra/ssim/master/README.md
4. **Commercial fallback if LibreOffice gaps are unacceptable:** benchmark Aspose.Slides. It is a viable headless renderer with direct slide-to-image APIs and custom sizing, but it is a licensed dependency and trial output is watermarked. Source: https://docs.aspose.com/slides/python-net/convert-slide/

# Open questions

- Do we want a truly headless, local-only pipeline, or is a dedicated PowerPoint machine acceptable as the ground-truth renderer?
- Does the deck corpus include enough PowerPoint-specific effects, fonts, SmartArt, chart types, or grouped shapes that LibreOffice’s documented PPTX gaps are likely to matter in practice?
- If LibreOffice fidelity is not good enough, are we willing to take on a commercial SDK dependency such as Aspose.Slides?
